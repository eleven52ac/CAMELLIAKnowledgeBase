# 05 · 模块、包与虚拟环境

> [!tip] 对应你熟悉的东西
> 模块 ≈ 一个 `.java` 文件,包 ≈ 一个 package,pip ≈ Maven/Gradle,虚拟环境 ≈ 给每个项目独立的依赖空间。

## 导入(import)

一个 `.py` 文件就是一个**模块**,直接拿来用:

```python
import math                    # 导入整个模块
print(math.sqrt(16))

from math import sqrt, pi      # 只导入需要的
print(sqrt(16))

from datetime import datetime as dt   # 起别名
print(dt.now())
```

## 自己拆文件

```
myproject/
├── main.py
└── utils.py        # 里面定义了 def add(a, b)
```

```python
# main.py
from utils import add
print(add(1, 2))
```

> [!note] `__name__ == "__main__"`
> 类似 Java 的 `main` 方法入口。只有「直接运行这个文件」时才执行,被 import 时不执行:
> ```python
> if __name__ == "__main__":
>     print("直接运行才会跑这里")
> ```

## pip:装第三方库

```bash
pip install requests          # 装包
pip install requests==2.31.0  # 指定版本
pip uninstall requests        # 卸载
pip list                      # 看装了啥
pip freeze > requirements.txt # 导出依赖清单(类似 pom.xml)
pip install -r requirements.txt  # 按清单安装
```

## 虚拟环境 ⭐ 一定要养成习惯

避免不同项目的依赖打架(Java 靠 Maven 自动隔离,Python 要手动建):

```bash
# 在项目目录下创建,生成一个 venv 文件夹
python -m venv venv

# 激活
venv\Scripts\activate        # Windows
source venv/bin/activate     # macOS / Linux

# 激活后命令行前面会出现 (venv),此时 pip 装的包只属于这个项目
# 退出
deactivate
```

> [!warning] 习惯
> 每开一个新项目就建一个 venv,并把 `venv/` 加进 `.gitignore`,只提交 `requirements.txt`。

## 标准库里几个后端常用的

| 模块 | 干啥 |
|------|------|
| `json` | JSON 序列化/反序列化 |
| `datetime` | 时间日期 |
| `os` / `pathlib` | 文件路径操作 |
| `logging` | 日志(别用 print 打日志) |
| `typing` | 类型注解辅助 |

```python
import json
data = {"name": "Tom", "age": 30}
s = json.dumps(data)          # 对象 → JSON 字符串
obj = json.loads(s)           # JSON 字符串 → 对象
```
